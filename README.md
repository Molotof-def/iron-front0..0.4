# IRON FRONT 0.5.0 — 3D BASE UPDATE

Telegram Mini App — тактическая стратегия на React + TypeScript + Vite + Three.js. Версия 0.4 добавляет проверку Telegram WebApp `initData`, облачные сохранения в PostgreSQL и конфигурацию развёртывания Render.

## Обновление 0.5.0

- Трёхмерная сцена главной базы на Three.js: камера с вращением и масштабированием, здания, дороги, растительность и техника.
- Режим строительства: оборонная башня, генератор и склад ресурсов. Размещение сохраняется в игровом сохранении и синхронизируется тем же облачным механизмом.
- Существующие API, Telegram WebApp authentication, PostgreSQL JSONB saves и battle loop сохранены.
- 3D-объекты процедурные и не требуют скачивания внешних моделей.

## Локальный запуск

Требуется Node.js 20.19+ или 22.12+.

```bash
npm install
cp .env.example .env
npm run dev
```

Откройте http://localhost:5173. Для локального API и Telegram-бота в другом терминале выполните `npm run server`.

## Публикация на Render

В корне есть `render.yaml` (Render Blueprint). Он описывает один бесплатный Node Web Service и бесплатный PostgreSQL в регионе Frankfurt.

1. Загрузите весь проект в GitHub. Не загружайте `.env`, токен или личные данные.
2. В Render выберите **New → Blueprint** и подключите репозиторий.
3. Проверьте план ресурсов и подтверждайте создание только если согласны с выбранными тарифами.
4. В настройках сервиса задайте `TELEGRAM_BOT_TOKEN` (секрет от @BotFather).
5. После первого deploy скопируйте HTTPS-адрес сервиса и укажите его в `MINI_APP_URL`. Сохраните переменные и дождитесь повторного deploy.
6. В @BotFather настройте Mini App / Web App на этот HTTPS-домен.
7. Откройте бота и отправьте `/start`. Он пришлёт приветствие и кнопку открытия игры.

На Render бот использует Telegram webhook, а локально — long polling. Это позволяет Render получать команды через входящие запросы, не полагаясь на постоянно работающий фоновый процесс.

**Важно о бесплатной базе Render:** бесплатный PostgreSQL имеет ограничение по объёму и сроку жизни — Render удаляет бесплатную базу через 30 дней после создания (после этого есть ограниченный период для перехода на платный тариф). Для долгосрочного хранения прогресса нужно заранее перейти на подходящий платный тариф или настроить перенос резервной копии. Не храни единственную копию важных данных в бесплатной базе. Смотри актуальные условия Render перед подтверждением: https://render.com/docs/free

### Переменные окружения

- `TELEGRAM_BOT_TOKEN` — токен бота, секрет.
- `MINI_APP_URL` — публичный HTTPS URL опубликованной игры.
- `DATABASE_URL` — Render передаёт автоматически из PostgreSQL.
- `PORT` — Render передаёт автоматически.
- `DISABLE_BOT_POLLING` — `true`, чтобы временно выключить long polling.

## Серверные API

- `GET /api/health` — состояние сервиса, бота и базы.
- `POST /api/auth` — проверка подписи Telegram `initData` на сервере.
- `GET /api/save` — загрузка сохранения текущего Telegram-пользователя.
- `PUT /api/save` — сохранение прогресса текущего Telegram-пользователя.

Сохранения привязаны к Telegram ID, а не к переданному клиентом имени. Подпись `initData` проверяется HMAC-SHA-256 с использованием токена бота; устаревшие данные отклоняются. Секретный токен никогда не передаётся фронтенду.

## Что важно знать

- Внутри Telegram Mini App игра пытается загрузить и синхронизировать сохранение с PostgreSQL. В обычном браузере остаётся локальное сохранение.
- Облачная синхронизация отправляет изменения с небольшой задержкой. Пока нет соединения, локальный прогресс остаётся на устройстве. При одновременной игре на двух устройствах действует принцип «последняя запись побеждает».
- Это первая версия облачных сохранений, а не полноценная защита от читов: игровую экономику и выдачу наград в будущем нужно переносить на сервер.
- Суточные операции пока хранятся локально и не синхронизируются между устройствами.
- Не публикуйте Telegram-токен и `DATABASE_URL`, не вставляйте их в переписку и не коммитьте `.env`.
