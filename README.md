# IRON FRONT v2.3.0

Танковая стратегия (Telegram Mini App): база, ангар, исследования, операции, задания. **Вся игровая логика и таймеры теперь на сервере.**

## Что изменилось
- **Сервер — единственный источник правды.** Клиент отправляет только намерения (`POST /api/game/...`); цены, награды, результат боя и время считает сервер. Таймеры строительства, производства и исследований идут по серверным меткам, ресурсы копятся и офлайн.
- **Новое:** 8 зданий (штаб, ангар, завод, склад, лаборатория, ремонт, полигон, РЛС), электроэнергия, 27 танков в 5 классах с разными ролями, 24 технологии в 6 ветках, 15 операций 5 типов, пошаговый бой (погода, арены, отряд до 3 машин), ежедневные задания, достижения, журнал событий, реальный рейтинг.
- **Дизайн:** тёмный тактический UI; две раскладки (мобильная — нижняя навигация и safe-area; ПК — боковая панель).
- **Безопасность:** проверка подписи initData, блокировка строки игрока (`SELECT … FOR UPDATE`), идемпотентные запросы (`requestId`), награда выдаётся один раз, лимит частоты, аудит `iron_events` без секретов.
- **Убрано:** `framer-motion`, `lucide-react` (заменены CSS-анимациями и встроенными иконками), `vitest` (тесты логики — `node --test`). Клиентский расчёт боя и рейтинг с демо-значениями удалены.
- `server/balance.mjs` — служебная симуляция баланса (`node server/balance.mjs`), в продакшене не используется.

## Новое в 2.3
- **Дуэли (PvP):** асинхронные бои против защитных отрядов других игроков и тренировочных противников; 6 жетонов в сутки, подбор по рейтингу, один и тот же соперник не чаще раза в сутки, рейтинг по системе Эло. Денежных ставок нет.
- **Сезоны рейтинга:** раз в месяц (по UTC) сброс с сохранением половины прироста; награды по лигам (Бронза → Алмаз), забираются один раз.
- **Экипаж и навыки:** опыт машины в боях даёт очки; 5 общих навыков + особый навык каждого класса; сброс за кредиты.
- **Бесплатный сезонный пропуск:** 30 уровней наград, опыт за бои, дуэли, задания, недельную цель.
- **Кланы:** создание (с 5 уровня), поиск, вступление, недельная цель клана и награда каждому участнику, до 30 человек.
- **Косметика:** 6 камуфляжей и 7 эмблем за достижения, видны в ангаре, бою и дуэлях; на силу не влияют.
- **Уведомления бота:** кроме готовности построек — топливо восстановлено, забытый бонус (16:00 UTC), начало события недели. Включаются по отдельности (по умолчанию включены только «готовность»).
- **Настройки:** звук (синтезируется, файлов нет), музыка, крупный шрифт. **Звания** командира по уровням. **Карточка победы:** отправка в чат и сохранение картинкой.
- **БД:** миграция 4 — колонки `rating`, `has_defense`, `clan_points`, `clan_week` и таблицы `iron_clans`, `iron_clan_members` (только добавление). Дополнительные миграции (3 и выше) теперь «мягкие»: если одна не применилась, основная игра работает, а новые функции отключаются; причина пишется в лог `[db]`.
- **Не сделано:** английский язык — нужен перевод ~400 строк контента сервера и интерфейса, отдельный этап.

## Новое в 2.2
- **Уведомления бота:** когда достроилось здание, выпущен танк или завершено исследование, бот пишет в Telegram с кнопкой «Открыть IRON FRONT». Включается/выключается в «Профиль → Уведомления бота». Проверка раз в 30 секунд; каждое событие отправляется не более одного раза; если игрок заблокировал бота, уведомления для него отключаются.
  **Важно для Render Free:** бесплатный сервис засыпает после ~15 минут без запросов, а спящий сервер не может слать уведомления. Чтобы они приходили вовремя, настройте бесплатный пинг (например, UptimeRobot) на `https://<ваш-сервис>.onrender.com/api/health` каждые 5 минут либо перейдите на платный тариф.
- **Реферальная система:** ссылка вида `t.me/<бот>?start=ref_<id>`. Приглашённый получает стартовый бонус, пригласивший — награду за каждого друга, достигшего 3 уровня командира, и бонусы за 3/10/25 друзей. Приглашённым считается только новый игрок; себя пригласить нельзя; награда выдаётся один раз (сервер).
- **Недельные события** (ротация по неделям, Пн 00:00 UTC): повышенные награды за выбранные типы операций + недельная цель (8 побед).
- **Контент:** +5 танков (всего 32), +6 операций (всего 21) до уровня командира 28.
- **Графика:** детализированные танки (катки, гусеницы, камуфляж, люки), вспышки выстрелов, плавающие цифры урона, дым и огонь у повреждённых машин, свечение редкости, мягкая анимация витрины.
- **БД:** миграция 3 добавляет колонки `next_event_at`, `notify_enabled` в `iron_players` и таблицу `iron_referrals` (только добавление).
- **Не вошло:** PvP-дуэли — требуют отдельного продуманного дизайна защиты от накрутки рейтинга и проверки на реальной БД; рекомендуется следующим этапом.

## Новое в 2.1
- **Обучение для новичков** («Курс молодого бойца», 6 шагов): шаги и награды проверяет сервер (нельзя забрать награду, не выполнив шаг, и нельзя забрать дважды). Подсказка ведёт на нужный раздел, нужная кнопка навигации подсвечивается, обучение можно пропустить. Игроки, у которых уже есть прогресс, обучение не видят.
- **Справка командира** (кнопка «?» / «Справка», также по нажатию на ресурсы): ресурсы, энергия, классы танков, правила боя.
- **Ежедневный бонус** с серией на 7 дней (сервер проверяет «раз в сутки»), окно «Пока вас не было», метка «Рекомендуем» у операций, памятка «Как играть в бою», автопрокрутка к панели деталей на телефоне, уведомления вверху экрана.
- Новых таблиц и переменных окружения нет: формат состояния дополняется автоматически при следующем входе игрока.

## База данных (миграции только добавляют, ничего не удаляется)
Выполняются автоматически при старте (`schema_migrations`, advisory-lock):
1. baseline — `player_saves` как в v0.4.0 (без изменений);
2. `iron_players` (состояние игрока JSONB, xp, level, wins) и `iron_events` (аудит).

Старые сохранения: при **первом входе** игрока в v2 прогресс (кредиты, сталь, наука, XP, танки и их уровни, здания, исследования, статистика, позывной) один раз копируется из `player_saves`. Арсенал → Склад ресурсов; старые технологии → новые ID с достройкой зависимостей. `player_saves` не меняется. `PUT /api/save` оставлен для старых клиентов, но на игру v2 больше не влияет. Импорт доверяет старому сохранению один раз (значения ограничены разумными пределами), т.к. оно хранилось на клиенте.

## Переменные окружения
Обязательных новых нет. Необязательные: `BOT_USERNAME`, `DISABLE_NOTIFICATIONS`. Только для локальной работы: `ALLOW_DEV_AUTH` (вход без Telegram; в production выключен всегда), `GAME_TIME_SCALE` (ускорение таймеров для проверки; в production игнорируется).

## Локальный запуск
```
npm install
npm run dev:all        # Vite (5173) + сервер (3001)
```
Откройте http://localhost:5173. Без `DATABASE_URL` сервер хранит данные в `data/dev-store.json` (только для разработки). Быстрая проверка таймеров: `GAME_TIME_SCALE=60`. Тесты: `npm test`. Типы и сборка: `npm run typecheck`, `npm run build`.

## Обновление на Render (по порядку)
1. Сделайте резервную копию БД (Render → PostgreSQL → Backups или `pg_dump`).
2. Залейте код в репозиторий. `render.yaml` и команды (`npm install && npm run build`, `npm run server`) не менялись. Сборочные зависимости (vite, typescript, tailwind, @types) перенесены в `dependencies`, чтобы сборка работала при `NODE_ENV=production`.
3. Дождитесь деплоя. В логах должно появиться `[db] миграция 2 (server_authoritative_game_state) применена`. Проверьте `/api/health` (`version: 2.0.0`).
4. Откройте игру из Telegram: существующие игроки получат перенесённый прогресс.
5. Откат: вернуть предыдущий деплой — таблицы v0.4.0 не тронуты.

## Что проверено, а что нет
**Проверено:** 46 автотестов сервера (включая обучение, бонусы, события, уведомления, рефералов, дуэли, сезоны, экипаж, пропуск, кланы) (движок, таймеры и офлайн-прогресс, ресурсы и лимиты, очереди, бой, награды без повторов, миграция сохранений, подпись Telegram, API, лимит частоты) — пройдены; симуляция баланса; запуск сервера и API по HTTP; клиент собран esbuild и прогнан в Chromium (Playwright) на 360×800, 390×844, 430×932, 768×1024, 1366×768 и 1920×1080 — без горизонтальной прокрутки и ошибок консоли; сквозной сценарий стройка → исследование → производство → бой → награда.

**Не проверено** (в среде не было сети): `npm install`, `tsc -b` с настоящими `@types/react` (типы проверены на упрощённых заглушках), `vite build`, **работа с реальным PostgreSQL** (код `pg-store` и миграций не запускался), реальная подпись Telegram с вашим токеном, поведение на iPhone/Android и внутри Telegram, обработка Tailwind. Первый деплой стоит проверить на копии БД.
